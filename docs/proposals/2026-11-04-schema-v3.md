# Result schema v3: windows, the collective map and the null's verdict (proposal)

PLAN 5.5, the result record. This is a design, written before any code.

**decision:** whether `result.json` moves to schema v3 when the first of D's collective find
([collective-find](2026-11-04-collective-find.md)) and A's null of the maximum ([verdict-null](2026-11-04-verdict-null.md))
passes its criteria, so that `locate` adopts both in one schema round.

**Why one round.** Each design changes what a record holds: D replaces the event fit with the detected window and the
pair rule with a map over (point, clock); A adds a threshold read from draws. Added one at a time, the report and the
benchmark's comparison would change twice and v2 would carry fields the other design retires. v3 is shaped so either
can land first: its candidate is a *mode* with a *matched set* of (window, flight, z), which describes the pair rule's
winner (two windows, plus extras) as well as the collective map's maximum (any number of windows).

## 1. Events become windows

`events` becomes `windows`, one per detected window entering the search (D: the top k = 10 by detect score):

| Field | What |
|---|---|
| `id`, `source` | `detect` or `saved_fit` |
| `bounds_s` | the window's start and end on the audio's timeline |
| `band_hz`, `harmonic_hint` | the detection band and the coarse tone's harmonic |
| `coarse_f0_hz` | `detect`'s grid-search tone, before any refinement |
| `coarse_heard_cpa_s` | the grid template's heard CPA: the clock prior only, never a measurement |
| `detect_score`, `detect_rank`, `score_kind` | for ordering and the detector's threshold |
| `gaps_s` | the invalid frames as [start, end] intervals (the valid mask, run-length, not per frame) |
| `null` | the window's own null: median, σ, n, seed, sample hash (`event_null`) |
| `match` | Maybe: at the winning mode, the flight, its pass (segment id and CPA time), harmonic, f0, shift and z |
| `utc` | Maybe: the heard CPA in UTC on the winning mode's clock |

Gone: v, d, `t_emission_cpa`, `t_steepest_fall`, f_pre, f_post and the fit's covariance. **The saved-fit path stays
in the same schema:** its windows are built from the committed fits (bounds = `window_s`, tone = f0, prior = t_cpa) and
each keeps the full fit under `legacy_fit`, allowed only when `source` is `saved_fit`. The saved-fit profile, kept as
the old path's benchmark, then compares field for field with `locate`.

## 2. The search and its modes

- **`search`:** `method` (`pair` or `collective`) and its settings: for `collective`, k, the f0 sweep (0.90–1.10), the
  residual shift (±8 s), the clock vote's cluster width (20 s) and minimum windows (2); for `pair`, the rule and
  silence distance. `pair_rules` stays as v2 has it when `method` is `pair`.
- **`candidates` become `modes`:** distinct candidates by PLAN's rule (farther than 2 km apart, or clocks a pass
  apart), best first. Each mode has lat, lon, its clock (`audio_minus_utc_s`, and for `collective` the windows that
  voted for it), its matched set (per window: flight, pass, z, with windows at z ≤ 0 listed as unmatched), m (matched
  flights), Z (the sum of the matched z), S_m = Z − κ(m − 2) when the null exists, and a refined point.
- **`collective`:** the map's maximum and its clock, the second mode and the ratio Z₂ / Z₁ (A's verdict reads both),
  and the map as a sidecar `collective_map.npz` (best Z per grid point and its clock), hashed in the record as
  `funnel_triples.npz` is today. For `method = pair` the triples sidecar stays as it is.
- **Provenance** adds the spectrogram's window, hop and window kind, since the window proposal may change them and a
  record must say which it was made with.

## 3. The verdict

`outcome` and `reason_codes` stay; the codes keep v2's list, including `competing_mode` and `below_null_threshold`.
New, Maybe until the null exists for the record's case:

- `null`: the statistic, the number of draws B, the draw days' seed and list (a sidecar `null_draws.npz` with every
  draw's maximum per m, hashed), the Gumbel fit per m (μ, β), γ_m (the 1 % point) with its 95 % bootstrap interval,
  κ (and MDL's value beside it, reported), the observed maximum's exceedance count among the draws and the 3/B bound.
- `winner`: the mode, its S_m, m, γ_m and the margin S_m − γ_m; `clearing`: every mode whose S_m clears its γ_m.
- `calibration`: what the threshold was calibrated on (development cases only) and that the verdict is experimental
  until the calibration group agrees. `located` is emitted only when exactly one mode clears.

## 4. What the report draws, changed once

`render_report` dispatches on `schema_version`: v1 and v2 pages are drawn exactly as today. For v3:
- **Map:** the collective map (or the pair triples) with every mode numbered, its region, and the refined points.
- **Verdict panel:** each mode's S_m against its γ_m with the bootstrap interval; the null's Gumbel fit over the
  draws' maxima, with the observed maximum marked; the second mode's ratio.
- **Windows:** one row per window (bounds, band, tone, detect score, gaps, z at the winner), and the overlay of the
  matched flight's own modelled curve at the winning mode. There is no straight-pass curve, except a saved-fit
  window's `legacy_fit`, drawn as today.
- **Matched set:** per mode, which window each flight explains and with what z; unmatched windows listed.

## 5. Migration

- `SCHEMAS` keeps 1 and 2 beside 3, and `validate` checks each record against its own version. No record is
  rewritten; v1 and v2 stay readable and renderable as they are.
- The benchmark's comparison reads either: a v3 record's true pair counts as found when the winning mode's matched set
  holds both true flights. A run's records share one version, recorded in `run.json`; `bench compare` across versions
  compares only the fields both carry and says so.
- The test fixtures gain v3 records (pair and collective, located, competing modes, below threshold, no null yet); the
  v1 and v2 fixtures stay.

## Fields agreed with the two designs (2026-11-04, after acceptance)

Agreed in one message each way, so D's and A's code write them from the start.

**With SDE-D (the collective find).**
- `windows[i].score_kind` is "brightness (mean whitened dB along the curve)", as `EventWindow.sweep_scores` computes
  it; scores and nulls are in those units.
- `windows[i].null` is `{"coarse": N, "fine": N}`, from `collective.window_nulls` (the search is coarse to fine). Each
  N is `{"median", "sigma", "n", "seed", "sample_sha256", "f0_sweep": [lo, hi] as fractions of the coarse tone,
  "anchor_s"}` (audio seconds). A match's z is against `fine`.
- `windows[i].match`, and each entry of `modes[k].matched` with `"window"` added: `{"flight", "segment",
  "pass_cpa_utc", "harmonic", "f0_hz", "shift_s", "score", "z"}`. `harmonic` is always 1 for now: the search sweeps f0
  around the coarse tone at h = 1 and chooses no harmonic. `shift_s` is the window's own best clock minus the mode's
  clock (the bin the windows agree on within ±6 s), up to about ±8 s.
- `modes[k].clock` adds `"voters"`: the windows with candidates in the winning point's agreeing bins.

**With SDE-A (the null of the maximum).** `verdict.null` as in section 3, with m keys as strings, and:
- `exceedances_at_observed` (draws at or above the observed S_m) and `exceedances_at_gamma` (draws above γ_m), each
  per m, beside the 3/B bound;
- `fit_check`: per m, `{"ks", "n"}`, the Gumbel fit's KS statistic; the probability plot is derived from
  `draws_file` (arrays `day`, `m`, `max_S`, `second_S`), not stored;
- `draws_without_candidate`: per m, draws whose search kept no candidate (`max_S` NaN, left out of the fit);
- `day_shift`: "whole days onto the recording's date" when the draws were searched with `locate`'s clock gate, which
  needs each other day's traffic at the recording's date and hour. The gate is in `locate` only, so the saved-fit arm
  needs no shift.
- `verdict.winner`: `{"mode", "m", "Z", "S_m", "gamma_m", "margin"}`; `verdict.clearing`: mode ranks; `verdict.calibration`.

## Decision line

- **v3 is adopted when the first of the two designs passes its criteria,** and only the passed design's fields are
  filled; the other's stay Maybe with the reason. If D passes first, v3 lands with `windows`, `collective` and modes,
  and `verdict.null` waits. If A passes first, on the saved-fit arm, v3 lands with modes, `legacy_fit` windows and the
  null, and `collective` waits.
- **If neither passes,** v2 stays and this proposal waits; nothing of it is built ahead.
- **If the schema has to change after the first lands** (a field either design needs that isn't here), that is v4,
  not an edit to v3.
